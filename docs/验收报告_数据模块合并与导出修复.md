### 3. 两个架构决策的落地

- **B1 任务级绑定**：`quote_jobs.database_key` 记录任务所用价目库；`process_job` 通过 `session_for_key()` 从该库读取价目本，**不改动全局激活库**，多库可被不同任务并发使用。
- **键名分离**：`key` 为 ASCII 文件名键（`data/{key}.db`），`display_name` 为任意中文显示名；重命名只改显示名，不动文件，因此不牵动全局 engine、WAL/SHM 兄弟文件与已绑定任务。

## 二、修复的缺陷

### 主缺陷：多方案导出后续方案缺描述列

`create_export()` 只为「报价1」补齐 品牌/制造商/型号/产品编码/规格，额外方案硬编码为「单价 + 制造商」。

**修复**：新增 `EXTRA_OPTION_FIELDS = ("单价", "制造商", "品牌", "型号", "产品编码", "规格")`，为每个额外方案生成完整列组；型号与产品编码同取产品编码，与「报价1」口径一致。

### 次生缺陷 1：空列组

`extra_option_count = requested_option_count - 1`，与实际选中方案数无关；方案数填 3 而整单只选 1 个方案时会留下整组空列。

**修复**：按**实际会写出的**最大方案数生成列组。

### 次生缺陷 2：未确认行泄露候选价（本次新发现）

「报价1」有 `line.confirmed` 判断，但「报价2~N」无条件写入。结果是客户版询价单里，未确认行的报价1 为空、报价2/报价3 却有价——既口径不一致，也把未人工确认的候选价带给了客户。

**修复**：备选方案列与「报价1」采用同一条件 `(include_internal or line.confirmed)`；列组数量也改为只统计会被写出的行。已补回归测试。

### 次生缺陷 3：导航副标题与 Tab 文案不一致

导航项副标题写的是「库管理、价目、治理」，而页内 4 个 Tab 实际叫「数据库 / 价目导入 / 质量治理 / 审计事件」——用户按副标题找不到对应的 Tab。

**修复**：副标题改为「数据库、价目、治理」，与 Tab 文案对齐。此项由真实浏览器渲染验证发现。

> **后续变更（2026-09-22）**：本报告写完后，「数据库」+「价目导入」又合并成了「价目库」，4 个 Tab 变为 **价目库 / 表格编辑 / 质量治理 / 审计事件**，而副标题一直停留在「数据库、价目、治理」，于是重新出现同一类不一致（副标题里的"数据库"已经不是任何一个 Tab 的名字）。
> 现已更新为「价目库、表格编辑、治理」。上面第 85 行与验收表中的「数据库、价目、治理」是 **2026-09-21 的当时状态**，保留作历史记录。

### 次生缺陷 4：「最近常用 5 个」退化成「名称前 5 个」

`registry.recent_entries()` 只按 `last_used_at` 倒序。新建但**尚未使用过**的库该列为 NULL，会一起掉到末尾并按 `display_name` 排序——于是默认的「最近常用 5 个」实际是「名称字母序前 5 个」，用户刚建好的库反而不出现在选择列表里。

**修复**：排序键改为 `coalesce(last_used_at, created_at) DESC`，即"用过按最近使用时间，没用过按创建时间"。搜索的同分并列也改用同一套取值。已补回归测试（测试用例特意按升序命名 1..7，使"按名称"与"按时间"结果不同，旧实现必失败）。

## 四、注意事项

1. **`赛特尔25年.xls` 本身没有品牌/制造商列**。用它做数据源时，导出的 品牌/制造商 列为空属正常，不是缺陷；需要非空样本请用 `高中理化生报价.xlsx`（含「品牌」「制造商名称」列）。
2. **测试夹具目录**：`backend/tests/test_excel_service.py` 需要真实询价单，现按 `QUOTE_TEST_DATA` 环境变量 → `<工作区>/测试数据` → `E:\Browser Download\测试数据` → `E:\Browser Download\数据库文件` 顺序查找，找不到则跳过用例（不再整套报错）。工作区根目录下存在一份临时副本 `测试数据/`（4 个 xlsx，约 1.2 MB），删掉不影响测试（会自动回退到 E 盘）。
3. **切库会让在线会话失效**：`activate` 是进程级热切换，旧库的 `auth_sessions` 不在新库中，接口会为当前用户重建 cookie。属既定设计，单机单用户可用，高并发场景需另行改造。
4. **回收站与备份**：删除前自动备份到 `data/_backup/`，文件移入 `data/_trash/`。彻底删除不可恢复。
5. **`vinext dev` 同一目录只允许一个开发服务器实例**，重复启动会提示已存在的 PID 并给出 `taskkill` 命令。想与已开的 dev server 并存，只能用 `npm start`（生产模式）另起端口。
6. **排查端口时请用 `localhost` 而不是 `127.0.0.1`**：`vinext dev` 只绑定 IPv6（`[::1]:3000`），而本机若设置了 `http_proxy`/`HTTP_PROXY` 环境变量，curl 会走代理、以 IPv4 回环连接而失败，表现为 `502 upstream connect failed`——看起来像"开发服务器挂了"，其实服务完全正常，用 `http://localhost:3000` 访问即可（生产模式的 `vinext start` 绑定 IPv4，因此 `127.0.0.1` 可用）。
7. **验收方式说明**：前端不是只做静态检查，而是用系统 Chrome 无头模式 + CDP 真实渲染并交互（登录、点导航、逐个切换 Tab、读取选择器列表），因此能发现纯静态检查看不到的问题（本次的导航副标题不一致就是这样查出来的）。
