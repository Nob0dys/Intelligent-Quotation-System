**三个结构性事实：**

1. **数据库是进程级全局热切换**。切换会换绑全局 engine，旧库的 `auth_sessions` 随之失效，代码专门重建了当前用户 cookie（`main.py:1654-1671`）——即"切库 = 所有人掉线一次"。当前设计对单机单用户可用，但对并发不友好。
2. **库没有任何元数据**。`_db_stats()` 每次请求实时打开每个 `.db` 文件 `COUNT(*)`；没有中文名、创建时间、使用记录。库一多，列表接口会线性变慢。
3. `DATA_DIR = ./data`（相对 `demo-app/backend`），交付包根目录的 `data/quote_saitel.db`（257 MB，赛特尔25年）**不会被自动加载**，需要手工放入 `demo-app/backend/data/` 或设 `DATABASE_URL`/`QUOTE_DATA_DIR`（见 `docs/交接文档_demo-app报价执行.md`）。

### 1.4 中文库名：可行性实测

| 试验 | 结果 |
|---|---|
| `create_engine("sqlite:///./data/中文库名.db")` 建表+读写 | ✅ 正常，文件正确落盘 |
| 含空格 `测试 库.db` | ✅ 正常 |
| `sqlite3.connect("file:data/中文库名.db?mode=ro", uri=True)`（`_db_stats` 用的方式） | ✅ 正常 |

**结论**：中文文件名在技术链路（SQLAlchemy / sqlite3 / NTFS / JSON 传输）上全程可用。真正的阻塞点只有两处正则：

- 后端 `database.py:83` `re.fullmatch(r"[A-Za-z0-9_-]+", db_name)`
- 前端 `QuoteApp.tsx:1390` `/^[A-Za-z0-9_-]+$/`

**但仍不建议让文件名 = 显示名**，原因是"重命名"：改文件要同时处理全局 engine 重绑、WAL/SHM 兄弟文件、已绑定该库的报价任务、`exports/` 目录引用，且 Windows 下文件被进程持有会删不动。→ 采用**键名分离**（§3.2）。

## 2. 方案选型

### 2.1 模块合并方式

| 方案 | 做法 | 评价 |
|---|---|---|
| A 纯 UI 合并 | 一个导航项，页内两个 Tab，后端接口不动 | 改动最小，但"库"与"治理"仍是两套概念，搜索/最近常用无处安放 |
| **B 领域模型合并（推荐）** | 一个导航项「数据资产」+ 4 个 Tab；后端统一 `/api/databases/*` 资源族；治理指标按库维度返回 | 语义一致，为"库搜索/最近常用"提供落点 |
| C 多租户资产平台 | 全量重构 | 过度设计 |

### 2.2 数据库名称（中文）实现方式

| 方案 | 做法 | 评价 |
|---|---|---|
| A 文件名即中文名 | 放宽两处正则 | 字面满足，但重命名 = 改文件，风险高 |
| **B 键名分离（推荐）** | `key`（ASCII，自动生成）↔ `display_name`（任意中文，可随时改） | 文件稳定、重命名零风险、UI 只呈现中文 |
| C 纯 hash 键 | `key = db_a1b2c3` | 排障困难，不推荐 |

推荐 B，用户视角是"输入中文名 → 直接用"，需求 1 完全满足。若用户坚持要目录里也是中文文件名，可开一个兼容档：`key` 也允许中文，但仍单独存 `display_name`，二者可不同。

### 2.3 报价与数据库的关系（**关键架构决策**）

| 方案 | 语义 | 评价 |
|---|---|---|
| A 维持全局热切换 | "新建报价"里的选库 = 切换当前库 | 最省事，但一次选库会重置所有在线会话，并发下会串库 |
| **B1 任务级绑定（推荐）** | `quote_jobs.database_key`；匹配从指定库读价目本 | 任务之间互不干扰，天然支持"最近常用" |
| B2 选择即切换（降级档） | 选库触发 `activate`，任务不记录库 | 1 天可交付，作为 B1 的过渡 |
| C 合并所有库 + 逻辑分区 | 单库多分区 | 改动最大 |

**推荐 B1**，理由是它同时满足需求 4 且不引入并发风险。B1 需要处理的四个技术点：

1. `services.py:442` `history = [... for item in db.scalars(select(HistoryQuote)).all()]` → 改为从**目标库的独立会话**读取。
2. `excel_service.py::_build_spec_alias_cache(db)` → 传入目标库会话。
3. 回写链路（`/api/price-drafts/{id}/review` → `HistoryQuote`，`main.py:1400+`）必须写回**同一个库**。
4. 匹配缓存在 `matching.py` 是 `lru_cache`（键为文本，非库 ID），不同库的记录产生不同键 → **无正确性问题**，只需注意缓存总量（`maxsize=1048576` 那层）。任务级绑定后 `warmup_match_caches()` 按库预热即可。

### 2.4 元数据（中文名 / 最近使用）存放位置

| 方案 | 评价 |
|---|---|
| **独立控制库 `data/_registry.db`（推荐）** | 不随业务库热切换而丢失；支持并发写、审计 |
| 写在当前业务库里 | 一切换就丢，不可用 |
| JSON 文件 `data/_registry.json` | 更轻，但并发写需自行加锁 |

推荐独立控制库；`database.py` 新增 `registry_session()`，与热切换的 `SessionLocal` 完全解耦。注意 `list_databases` 需把 `_registry` 与 `_trash`/`_backup` 一并排除。

```
normalize_name(s):

  s = s.strip().lower()
  s = re.sub(r"[\s_\-·．.]+", "", s)         # 去空格与常见分隔符
  return s
```

### 3.4 搜索与最近常用：匹配与排序逻辑

#### 定义"一次使用"（决定 `last_used_at` / `use_count` 何时更新）

只统计三种**有业务含义**的事件，避免浏览行为把排序噪声化：

1. 被设为当前激活库（`activate`）
2. 被某个报价任务选中为匹配库（`create_quote_job` 带 `database_key`）
3. 被导入价目本（`import`）

> 仅打开列表 / 搜索 / 查看详情**不计数**。

#### 最近常用（默认态）

```
query = registry.filter(status == "active")
             .order_by(last_used_at.desc(), use_count.desc(), display_name.asc())
             .limit(5)
```
`last_used_at` 为 NULL 的新库排在末尾，回落到 `created_at desc`。

#### 搜索匹配与打分

输入 `q` → `nq = normalize_name(q)`（NFKC + 小写 + 去空格/分隔符）。

| 命中方式 | 分值 |
|---|---|
| `display_name` 前缀命中 | 100 |
| `display_name` 子串命中 | 60 |
| `key` 前缀 / 子串命中 | 40 |
| `tags` 命中 | 25 |
| `note` 命中 | 15 |

无任何命中 → 剔除。

排序：
```
ORDER BY score DESC,
         last_used_at DESC,
         use_count DESC,
         display_name ASC
```

**要点**：`use_count` **不参与打分**，只作为同分时的并列打破。否则搜"高中"时会把一个常用但无关的库顶上来，看起来像随机结果。

空查询（`q` 为空）→ 直接走"最近常用 top5"，即需求 4 的默认态。

`scope` 参数：
- `recent`（默认，limit=5）：先给最近常用，`q` 非空时在**全量 active 库**上搜索并同样 limit；
- `all`：搜索全部，用于"查看全部"展开。

#### 可选增强（二期）

拼音首字母：`赛特尔` → `ste`。用一张轻量汉字首字母映射表，不引第三方依赖；命中记 50 分。可显著提升中文库名的检索效率。

## 8. 风险与边界

| # | 风险 | 处置 |
|---|---|---|
| 1 | 热切换会重置所有在线会话（现行为） | 合并后明确提示；P3 的任务级绑定可彻底规避 |
| 2 | Windows 下库文件被进程持有，删除会失败 | 删除前 `engine.dispose()`；搬移时连带 `-wal`/`-shm` |
| 3 | 中文名归一化冲突（`赛特尔25年` vs `赛特尔 25 年`） | 统一走 `normalize_name()` 判重 |
| 4 | key 撞上 Windows 保留字（`con`/`nul`/`com1`…） | 生成时加前缀 `db_`，或黑名单校验 |
| 5 | `_db_stats()` 每次实时 count，库多时列表变慢 | 统计结果按文件 mtime 缓存进注册表 |
| 6 | 大库（`quote_saitel.db` 257 MB / 4131 条） | 列表接口不做全表扫描；`COUNT(*)` 加超时保护 |
| 7 | 导出表头与原表列名冲突 | `ensure()` 已实现"原表已有则复用"，保留该行为；回归测试断言无重复列 |
| 8 | 删除库后历史任务无法回放 | 保留 `database_name_snapshot`；回收站默认保留 30 天 |
| 9 | 切换库后旧库的任务记录不可见 | 文档明确"任务是库内数据"；跨库汇总留待二期 |
