# 智能报价系统 · 说明与使用教程

> 供评审体验使用。本文档对应当前最新版本（含客户分组、手工方案、批量导入等功能）。

## 一、系统是什么

一套面向采购报价场景的 Web 系统：上传客户询价 Excel，系统在历史报价库中自动匹配每个商品的候选报价（规则评分匹配），人工在"确认列表"中复核、挑选方案后，一键导出填好报价的 Excel。

- **前端**：React 单页工作台（无第三方组件库，手写 CSS），负责全部交互。
- **后端**：FastAPI + SQLAlchemy，负责 Excel 解析、匹配评分、导出、账号与客户管理。
- **数据库**：本机开发默认 SQLite（零配置）；服务器部署用 PostgreSQL（Docker Compose 自动拉起）。
- **部署**：Docker Compose（6 个服务：postgres / api / worker / backup / web / proxy），目标环境是 Windows 服务器（Docker Desktop + WSL2），局域网网页访问。

分工说明：前端与系统集成为一方负责；匹配算法（属性稀疏矩阵精确规则匹配 + NLP 语义匹配兜底）为另一方负责。当前匹配引擎是纯规则加权评分（`backend/app/matching.py`），NLP 兜底尚未接入，算法侧可直接替换该模块。

## 二、启动教程

### 方式 A：本机快速体验（推荐给评审）

需要 Node.js 22+ 和 Python 3.12+。

```bash
# 终端 1：启动后端（首次先装依赖）
cd demo-app/backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```bash
# 终端 2：启动前端（demo-app 目录）
cd demo-app
npm ci        # 首次
npm run dev
```

浏览器访问 `http://localhost:3000/`。

- 历史报价种子数据由 `npm run dev` 前置脚本从 `../测试数据/*.xlsx` 自动生成（`public/demo/history.json`），后端首次启动时灌入 SQLite（仅当库为空）。
- 想清空重来：停掉后端，删除 `backend/data/` 下的 sqlite 文件再重启即可。

### 方式 B：Windows 服务器 Docker 部署

```powershell
cd demo-app
copy .env.example .env   # 然后编辑 .env，改掉数据库和两个账号的初始密码
docker compose up -d --build
docker compose ps        # 确认 6 个服务都 Up
```

局域网访问 `http://服务器IP:8080/`。备份容器默认每 24 小时自动备份数据库和文件，保留 14 天（详见 README.md）。

## 四、使用教程（完整业务流程）

### 第 0 步：准备历史报价库（admin）

系统自带一份完整价目。要换成真实数据，进左侧 **数据资产**（"数据治理""数据库管理""价目导入"已合并到这一个入口，页内分 4 个 Tab）：

- **价目库**（Tab 1）：新增/重命名/编辑/删除价目库。库名支持中文，重命名只改显示名、不动底层文件；删除走回收站（先自动备份，可恢复，彻底删除需输入库名确认）。**系统默认库不可删除**。
  - **新建价目库（命名 + 上传一步到位）**：点右上角 **＋ 新建价目库**，在**同一张卡片**里填好库名、选上价目本 Excel，点 **创建并导入**——系统先建库、紧接着把价目本导进去，一次提交完成两件事，不用"先建空库、再滚回去选库上传"。不选文件则按钮变成 **创建空库**，只建一个空库稍后补传。
  - **给已有库补传**：用「导入价目本到已有库」卡片选目标库 + 选文件上传。
  - 上传的 Excel 需含名称列和价格列，表头支持"单价/价格/报价"及"赛特尔单价"这类变体，遍历所有 sheet。完成后显示"新增 N 条 / 重复跳过 M 条 / 无效 K 条"。重复判定：名称+参数+单位+制造商+价格全一致才算重复。
  - **建库成功但导入失败时卡片不会关**：直接点 **重试导入** 即可，不会重复建库、也不会建出两个同名库。
- **表格编辑**（Tab 2）：像 Excel 一样直接增删改库里的价目行，也能**打开一份本地 Excel 价目本**跟库里比对后一键对齐，改完保存回数据库。详见下方"表格编辑怎么用"。
- **质量治理**（Tab 3）：查看所选库的记录数、冲突与去重情况等治理指标，并提供**一键去重**（按上述规则合并重复记录）。可选任意库查看。
- **审计事件**（Tab 4，仅管理员）：查看建库/改名/删库/导入/表格编辑等操作留痕。
- 左侧 **历史报价** 页可搜索库内记录，也可"手工录入"单条补录。

> **系统里没有"切换数据库"这回事。** 系统默认库是个常量，界面上不提供切换入口，所有没显式指定库的操作都落到它上面。选库只发生在**新建报价任务**那一刻——任务会记住自己用的库。需要多套价目时，点「＋ 新建价目库」填名称 + 选文件一次建好并导入，然后在建任务时选它。

#### 表格编辑怎么用（Tab 2）

给"导入之后想微调数据"的场景用——不用回原始 Excel 改完再整本重导。

1. 顶部选**编辑库**（默认系统默认库，也可改选任意库）。
2. 表格里点任意单元格直接改；改过的行会标黄，右上角"保存到数据库（N）"显示待保存数量。
   - **新增一行**：在表格最上方出现一条绿色草稿行，填好后一起保存。保存后来源记为"表格编辑"，便于追溯。
   - **删除**：行尾"删除"只是标记，保存后才真正从库里删；标记后上方会出现"撤销"入口。
   - **撤销**：把某一行的改动改回原值，该行的黄色标记会自动消失，不会占一次保存。
3. 点**保存到数据库**：只提交改动过的行（新增/修改/删除），**不做整表覆盖**，所以不会影响别人同时在导入的数据。保存前系统会自动备份整个库文件（保留最近 10 份，在 `data/_backup/`）。
4. 有问题的行会被**拒绝并说明原因**，不影响其它行写入：
   - **版本冲突**：这行在你编辑期间被别人改过。点"跳到该行"刷新后重改。
   - **重复冲突**：改后与库里另一条完全重复（名称+参数+单位+制造商+价格）。点"跳到该行"直接看到冲突的是哪一条。
   - **校验失败**：名称为空、单价为空/为负、数量不是数字。表格上方会先列出来，改完才能保存。
5. **导出 CSV**：把当前库（含当前筛选与未保存改动）导出成 CSV，用 Excel/WPS 直接打开。
6. **打开本地 Excel**：把一份价目本（.xlsx / .xls / .xlsm）带进来跟库里的数据比对，确认后一键写库。详见下方"打开本地 Excel 怎么用"。

两个必须知道的细节：

- 网格里的**单价是不含税基准价**。价目本里表头写"含税单价"的，导入时已按固定税率折算成税前价入库，导出报价时会再乘回税率——所以在网格里改价要按**税前**填。
- 保存是**管理员**权限；非管理员打开这个 Tab 是只读的。

#### 打开本地 Excel 怎么用

适合"手上有一份新价目本，想让它和库里对齐"的场景：改过价的自动认成修改，库里没有的自动认成新增，重复的、没价格的不会被误写进去。

1. 点工具栏 **打开本地 Excel**，选文件。系统开始解析，**这一步只是比对，不会改数据库**。
2. 弹出预览框，按三类分组（默认停在"将改动"）：
   - **将改动**：会新增的行、会修改的行、以及"需指定"的行。
   - **无需改动**：和库里完全一致的行。
   - **不载入**：文件里重复的行、没有有效价格的行。
3. 每行都写清楚了：器材名、来自哪个文件哪个 sheet 第几行、**按哪几个字段认定它们是同一件器材**、以及会改什么（`旧值 → 新值`）。
   - **不想写的行直接勾掉**（也可"全不选"），勾掉的行会灰显、标注"已排除，这次不写"。右下角按钮上的数字是**点下去实际会写几行**，会跟着勾选实时变化。
   - 如果库里同一个器材有多条（同名称同参数同单位但价格/制造商不同），会标成**需指定**，展开候选列表，每条都写了"选它会改什么"，点一下选中即可；不选的行会被跳过（点应用时会再确认一次）。
4. 点**应用并保存（N）**写库。保存前照例自动备份整个库文件；被拒绝的行（版本过期、改完与另一条重复）会落到表格上方的问题列表，点"跳到该行"直接定位。

两个容易踩的点：

- **文件里没有的列，更新时保留库里的原值**。比如价目本没有"品牌"列，那这次更新就不动品牌；但如果价目本**有**品牌列、只是某一行空着，那就表示"这一行品牌清空"，会真的清空。
- **匹配用的是名称+参数+单位+制造商**（不含价格，所以只改价会被认成"修改"而不是"新增"）。如果价目本**没有制造商列**，就退化成用名称+参数+单位匹配——匹配更松，撞上多条会提示"需指定"。反过来，如果文件里把制造商拼写改了，会被认成"新增"（因为制造商也是身份的一部分），预览里能看见，自己决定要不要应用。

### 第 1 步：（可选）建立客户档案

左侧 **客户档案** → 三个分组入口：**普通客户 / VIP 客户 / 特殊要求客户**，点进分组后搜索、新建、编辑、删除客户。

- 新建时客户类型由所在分组决定（不用重复选择）；编辑时可下拉转组。
- **VIP 客户**：可设协议折扣（自动作用到报价）、最低毛利线、偏好制造商（匹配加分），也可以附加特殊要求。
- **特殊要求客户**：必须至少一条结构化要求（属性如下拉建议的产品名称/型号/制造商/品牌/参数/单位 + 包含/≥/≤/= + 目标值 + 必须满足/偏好）。"必须满足"的要求不满足时会在匹配中标记阻断风险。

一次性生意可以不建客户，见下一步。

### 第 2 步：新建报价任务

左侧 **新建报价**：

1. **选择客户**：先点三大类，再在组内按名称搜索选择（列表按由新到旧排列）；列表第一项是"不关联客户（一次性报价）"，不选客户也能直接建任务（不应用折扣和客户要求）。
2. **选择价目库**：默认只列出**最近常用的 5 个库**，可直接点选；也能在搜索框里按中文名/备注/标签搜索全部库。选定后本次任务就固定读这个库的价目本，**不会影响其他人正在用的库**；不选则用系统默认库。
3. **选择询价文件**：客户的 Excel 询价单（表头识别支持"器材名称/设备名称"等变体；数量列若是 `=D7*2` 这类公式会取计算值作为计费数量）。
4. **报价方案数量**：1–5，默认记住上次选择。表示每个商品默认带出几个备选方案。
5. 提交后自动跳转任务中心，后台开始匹配。

### 第 3 步：确认列表（核心人工环节）

任务中心点进任务，进入确认列表：

- 商品默认**按匹配分升序**排列（低分在前，优先人工处理），点"评分"表头可切换降序/原表行号。
- 顶部有确认进度条（已确认 x / y 行）和异常筛选标签（待确认/需复核/无匹配…，带数量徽标）。
- 状态含义：**建议匹配**=高置信可直接确认；**待复核**=有候选但置信度不足或存在阻断风险，人工挑一个即可；**无可靠匹配**=没有候选或最佳低于 55 分，基本只能新建手工方案。
- 点某一行打开**候选方案抽屉**：
  - 卡片按评分排序，显示制造商/品牌/价格/评分分量/历史价区间；完全相同的卡片已自动去重。
  - 最多勾选 N 个方案（N=建任务时选的数量），**同一制造商的不同报价/参数可以同时选**，只有完全相同的方案才禁止重选。
  - 每个方案的价格都可手动改。
  - 对候选都不满意时，点底部 **＋ 新建手工方案**，自定义制造商/品牌/型号/参数/单位/价格，创建后自动选中；手工卡可删除。
  - 有阻断风险时可填写"覆盖原因"（选填），然后确认。
- **批量确认**：只自动确认高置信（≥80 分）且无阻断风险的行。

### 第 4 步：导出

任务详情工具栏 **导出 ▾**：

- **客户版**：原询价单右侧追加 数量 / 确认单价 / 税后单价 / 总价 / 税后总价 / 品牌 / 制造商 / 型号 / 报价单位；多方案时再追加 **报价2~N 列组，每个方案都带齐 单价 / 制造商 / 品牌 / 型号 / 产品编码 / 规格 六列**（旧版后续方案只有单价+制造商，本次已修复）；另附"多方案报价明细"sheet（含每个方案的数量、税后单价、小计与税后小计）。
  - 列组数量按**实际会写出的方案数**生成：整单只选了 1 个方案时不会留下空的 报价2/报价3 列。
  - 未确认的行在客户版**整行留空**（报价1 与 报价2~N 同一口径），不会把还没人工确认的候选价带出去；内部复核版则对所有行都写出。
- **内部复核版**：额外包含匹配状态、匹配分、风险提示、历史来源（手工方案会标注"手工方案"）。
- **税后价**：新建任务时可设税率（默认 10%，本地记忆）；任务详情中也能随时改税率；导出按 确认单价×(1+税率) 计算税后单价/税后总价。

任务卡本身支持**重命名**和**删除**（删除会清掉全部明细和文件）。

## 五、匹配规则速览（算法侧接口）

当前实现位于 `backend/app/matching.py`（纯 Python，无 NLP 依赖），替换算法时保持 `match_line()` 的输入输出契约即可：

- 文本规范化：NFKC + 去标点；相似度：bigram Dice + SequenceMatcher + 参数数值 token。
- 权重：参数 45 / 型号 15 / 名称 15 / 制造商品牌 10 / 单位 10 / 数据质量 5；产品编码精确一致直接 100 分。
- 阈值：<55 不可靠（不默认选中），≥80 高置信；单位可换算表内置，不可换算产生 `BLOCK:` 警告。
- 候选每行最多保留 12 条，落库前按"制造商+价格+参数+型号"去重；默认勾选 N 个不同制造商方案。
- 客户要求（special/vip）在评分阶段注入：必须满足项不满足 → `BLOCK:` 警告；偏好项/偏好制造商 → 加分。
- 匹配任务由独立 worker 进程轮询执行（开发环境内联），入口 `backend/app/services.py` `process_job()`。

### 匹配增强（真实生产数据实测后）

- 候选池合并：精确同名记录 + 通用名高分候选一起参与评分，避免"旧系统内部复核版"的错误确认价因精确同名被独大回灌。
- 规格变体一致性：数显/数字 vs 指针、量程/容量（g/ml/mm/A/V）、位数、MF 型号、档位功率不一致会降分并提示"规格变体不符"。
- 名称核心词：忽略 高中物理/高中生物 等学科前缀与尾部变体序号（游标卡尺1/2 视为同一产品），识别不同来源的同一商品。
- **产品编码**：`规格型号`列中的纯5位数字（教育装备 JY 码，如 04013 电子起电机）自动识别为"产品编码"，不再误显示在"型号"列；
  询价行参数/型号中的孤立5位码自动提取参与精确编码匹配；导出新增"产品编码"列。
- 自动带价门槛：名称核心词相似度 <0.30 或记录核心词未被询价核心词包含（如 仿真实验↔静电实验箱、条形强磁体↔蹄形强磁体）时不自动带价，转"无可靠匹配/需人工"。
- 数据注意：**不要**导入旧系统的"内部复核版"导出文件作为历史库（其中确认价本身可能是错误匹配回声），优先用 赛特尔/理化生/普教 等真实出价文件。历史库中已误导入的"内部复核版"记录会被剔除/建议手工清理。
- **含税价自动折算**：历史价列表头含"含税"（如 普教清单 的"含税单价"）时，导入自动按 `HISTORY_TAX_RATE`（默认10%）折回税前基准，导出税后 = 基准×(1+任务税率)，避免双重计税。

## 六、注意事项 / 已知边界

- 导出的"数量"取询价单原值，"总价"= 确认单价 × 数量；明细 sheet 每个方案有小计。
- 确认后的行若再改选方案，会自动退回"待复核"状态，需重新确认。
- 历史库的去重只在"完全一致"时合并；近似重复（规格文字微差）由候选卡去重在展示层兜底。
- **打开本地 Excel** 一次最多 5000 行、应用时一次最多 2000 行，超出会提示拆分；价目本解析器不返回"数量"与"报价日期"，所以打开文件不会覆盖库里这两个字段，它们仍在网格里手工维护。
- 测试：`cd backend && python -m pytest`（124 个用例）；前端 `npm run build`。
- 技术报告与正式版需求见 `deliverables/` 目录。
